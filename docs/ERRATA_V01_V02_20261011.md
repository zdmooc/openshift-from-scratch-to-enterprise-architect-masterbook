# Erratum — OCP 4.22 : système d'exploitation des compute nodes

**Date : 2026-10-11 · Affecte : Volume 01 édition 1.0 et Volume 02 édition 1.0, ainsi que le manuscrit courant du Volume 02.**

## Constat vérifié

Une formulation catégorique des premières éditions affirmait que **tous les nœuds OCP 4.22 doivent utiliser RHCOS**. Or la documentation Red Hat 4.22 disponible n'est pas entièrement cohérente :

| Source officielle | Contenu pertinent |
|---|---|
| [Release notes OCP 4.22](https://docs.redhat.com/en/documentation/openshift_container_platform/4.22/html/release_notes/ocp-4-22-release-notes) | Indique RHCOS requis pour control plane et compute |
| [Architecture OCP 4.22](https://docs.redhat.com/en/documentation/openshift_container_platform/4.22/html/architecture/architecture) | Indique RHCOS requis pour control plane et RHEL possible sur les compute nodes |
| [Installing on any platform OCP 4.22](https://docs.redhat.com/en/documentation/openshift_container_platform/4.22/html/installing_on_any_platform/installing-platform-agnostic) | Mentionne workers RHEL dans certaines installations |

## Correction de portée

**Règle éditoriale correcte :** le support du système OS d'un worker doit être vérifié selon le type d'installation, la version exacte, les notes/compatibilités et la matrice de support applicable; consulter Red Hat pour clarifier cette divergence. Ne pas imposer ni généraliser un worker RHEL pour OpenShift 4.22 à partir du seul guide Architecture, et ne pas exclure catégoriquement les configurations décrites dans la documentation d'installation.

Le control plane des installations standards doit utiliser RHCOS selon ces sources.

## Portée des éditions déjà publiées

Les PDF v01.0 et v02.0 restent conservés pour traçabilité. Leur formulation d'origine est historiquement datée et **cet erratum fait partie de leur documentation**. Une prochaine édition révisée pourra remplacer le passage concerné sans modifier les fichiers binaires déjà publiés.

## Exigence d'architecte

Pour une conception client, joindre au dossier l'extrait des documents de support et la validation spécifique de la plateforme/architecture plutôt que déduire l'éligibilité d'une configuration à partir d'une phrase isolée.
